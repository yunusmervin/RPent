# T8 · 知识叶子向量索引（可选后置）

依赖：T5、T7 ｜ 预估：1–2 天 ｜ 风险：中（触碰 merge 事务出口）

## 目标

把 global/task-family 知识叶子也向量化，新增 `search_knowledge` 工具，
让语义记忆召回不再只依赖大模型 grep。保留 grep 作为降级路径。

## 先读

- `docs/memory-redesign.md` 第 2.8 节
- `rpent/memory/manager.py` 的 `merge_memory`（发布叶子的位置）
- T5 的 `search_episodes` 实现（复用其模式）

## 要求

1. merge 事务发布叶子成功后，编码 `frontmatter + 正文首段（≤1000 字符）`，
   upsert 到 `leaves__<memory_version>` collection；冲突归档
   （`_internal/conflicts/`）**不**入索引；
2. collection schema：leaf_id（PK）、vector、scope、kind、suite、
   confidence、leaf_uri；
3. 新工具 `search_knowledge(query_text, scope?, kind?, top_k=5)`，
   readonly，行为对齐 `search_episodes`；
4. 索引失败不阻塞 merge（合并是事实源，索引可重建）；
5. `tools/rebuild_episode_index.py` 扩展支持 leaves collection 重建；
6. 提示词不动（本卡不改 prompts；若后续要让规划器优先用
   `search_knowledge`，另起任务卡单独评估）。

## 验收

```bash
pytest tests/unit_tests/ -q
pytest tests/unit_tests/episode/test_knowledge_index.py -q
# 效果验收（附输出）：
#   构造 3 条语义相近但措辞不同的 global 叶子，
#   search_knowledge 用人话提问能召回对应叶子；
#   merge 事务在 Milvus 不可用时仍正常完成
```

新增测试：冲突稿不入索引、索引失败降级、重建一致性。

## 禁止

- 不改 `merge_memory` 的合并/冲突/晋级语义；
- 不把已废弃（被 contradicted）的叶子从索引中静默删除——
  保留并由 confidence 字段表达。
