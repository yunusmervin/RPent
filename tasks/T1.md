# T1 · AGFS 存储后端

依赖：T0 ｜ 预估：2–3 天 ｜ 风险：中（外部组件接入）

## 目标

新增 `AGFSBackend`（`rpent/memory/agfs_backend.py`），实现 `MemoryBackend`
协议，把语料与帧存储挂到 AGFS；`--memory-backend agfs` 时启用。

## 先读

- `docs/memory-redesign.md` 第 1、2.1 节
- T0 产出的 `rpent/memory/backend.py`
- `rpent/utils/daemon.py`（ProcessDaemon，复用其进程管理风格）
- `rpent/utils/rpc/http_rpc.py`
- AGFS 官方文档（agfs-server 启动与 LocalFS/S3FS 插件配置）

## 要求

1. agfs-server 以独立进程启动（复用 `ProcessDaemon` 模式，
   端口 `pick_free_port()`，`--parent-watch`），支持
   `--agfs-endpoint` 直连已有实例（直连时不启动本地进程）；
2. 挂载点约定：
   - `/corpus/<robot>/` → LocalFS（指向现有 memory 目录，保证行为兼容）
   - `/frames/` → 本地目录（SHA256 两级目录分片内容寻址）；
     S3FS/SeaweedFS 挂载留配置项，本卡不做；
   - `/transcripts/` → LocalFS；
3. 帧写入 API：`put_frame(png_bytes) -> uri`，内容为键、已存在则复用；
4. 权限语义与 `FileSystemBackend._authorize` 完全对齐
   （机器人边界、评测只读、inbox 白名单）；
5. AGFS 进程启动失败时降级为 `FileSystemBackend` 并打 warning，
   主流程不炸。

## 降级路径（若 AGFS 接入受阻）

先交付"AGFSBackend 的 LocalFS 透传实现"（不依赖 agfs-server，仅用同一套
URI 约定 `agfs://frames/sha256/...` 映射本地目录）。契约测试必须相同。
agfs-server 真实接入作为本卡 follow-up commit。
