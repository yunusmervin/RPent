# T0 · 接口抽象：MemoryBackend

优先级：最高（一切后续任务的地基）｜ 预估：1–2 天 ｜ 风险：低（纯重构）

## 目标

把 `rpent/memory/manager.py` 的 `MemoryManager` 抽象为 `MemoryBackend` 协议，
现有实现更名为 `FileSystemBackend` 并保持行为逐字节不变。

## 先读

- `docs/memory-redesign.md` 第 2.1 节（接口契约）
- `rpent/memory/manager.py`、`rpent/memory/loading.py`、`rpent/memory/source.py`
- `rpent/tools/toolkit.py`（MemoryManager 的消费点）
- `rpent/cli/main.py` 中 `prepare_run_memory` 的调用方式

## 要求

1. 新建 `rpent/memory/backend.py`：定义 `MemoryBackend`（Protocol），
   方法签名与设计文档 2.1 节完全一致；
2. `MemoryManager` 改名为 `FileSystemBackend`（保留 `MemoryManager` 作为
   兼容别名一个版本，标 `DeprecationWarning`），文件内逻辑零改动；
3. 新增工厂 `get_memory_backend(name: str = "filesystem", **kwargs)`，
   未知 name 抛 `ValueError`；
4. 所有消费点（toolkit、loading、robot spec 的 `prepare_memory` 钩子）
   改为面向 `MemoryBackend` 编程；
5. `grep -rn "MemoryManager(" rpent/ robots/` 除兼容别名与工厂外无残留
   直接实例化。

## 验收（必须通过）

```bash
pytest tests/unit_tests/ -q                       # 零修改全绿
pytest tests/unit_tests/ -k memory -q
ruff check rpent/memory rpent/tools
grep -rn "MemoryManager(" rpent/ robots/ | grep -v backend.py   # 应为空
```

## 禁止

- 改动任何 `merge_memory` / `_authorize` 的逻辑行为；
- 改动测试断言；
- 引入新依赖。
